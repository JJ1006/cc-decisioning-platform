# ADR-0010: API tier (application-api, decision-query-api)

* Status: accepted
* Date: 2026-10-17

## Context and problem statement

P5 adds the first HTTP APIs: submit applications, record underwriter decisions, and read decisions, explanations and statistics.
mTLS and the gateway arrive in P6, JWT/OIDC later, so P5 has to be safe to replace piece by piece.

## Decision

* **Two services.** `application-api` (profile `edge`) writes: it only talks to Kafka (and to `decision-query-api`). `decision-query-api`
  (profile `analytics`) reads: it is the **only** service that reads Elasticsearch.
* **Single ES reader.** `application-api` needs the status of an application (and the id of the referral decision) and gets them from
  `decision-query-api` over HTTP, so there is one read model, one least-privilege Elasticsearch user and one place that maps documents to DTOs.
* **Read-only user.** Role `query_reader` (`read`, `view_index_metadata` on the `cc-*` read aliases, nothing else), user `decision-query-api`.
* **DTOs only.** No Elasticsearch document leaves the API as is. Indexed documents are already PII-masked by Logstash; DTOs add a second filter.
* **Manual decisions** go on `cc.decisions.manual.v1` and `cc.audit.v1`, reach `cc-decisions` through the same Logstash pipeline and carry
  `decisionSource=MANUAL` (automated decisions carry `ODM`). Statistics count automated (`ODM`) decisions: they hold the applicant summary
  and measure the rules; a manual decision answers a REFER, it does not change the rule outcome.
* **Role placeholder.** Until P6 (mTLS client certificate to role at the gateway) and the later JWT work, the caller role is the `X-Role` header
  and the underwriter id comes in the body. The header is trusted only because the gateway will strip and set it. Documented as a placeholder
  in `docs/api/README.md`; a missing role is 401, a wrong role is 403 plus an audit event with result DENIED.
* **Idempotency.** `Idempotency-Key` is kept in an in-memory cache (24 h, bounded): same key and same body replays the first response, same
  key and different body is 422. Lost on restart and not shared between replicas; a shared store (Redis or a Kafka-backed table) is a P10 item.
* **Errors** are RFC 7807 `application/problem+json` with a `correlationId` member. `X-Correlation-Id` is read or created and echoed.
* **Contracts.** OpenAPI is generated by springdoc, exported to `docs/api/*.yaml`, committed; CI regenerates and fails on drift, and lints
  with Spectral (`.spectral.yaml`).

## Consequences

* A decision-query-api outage makes status and manual decisions fail with 503 (submission still works: it only needs Kafka).
* Eventual consistency: a decision is visible after Logstash has indexed it (seconds). A fresh application has status SUBMITTED only in the
  instance that accepted it (in-memory), otherwise 404 until the decision is indexed.
* Fairness numbers use ODM decisions only; with a handful of documents a group ratio is noisy, so each group reports its sample size.
